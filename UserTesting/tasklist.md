| Capture     | You are preparing for your algorithms exam, and know that you'll need to be able to recall some of the key ideas behind mergesort's proof of correctness. Walk me through how you would make some quick notes.|Making points is required to do basically everything else in the app, so I need to know if users understand how to use them. As the designer, I know that notes are made in this app via brief points, but a user may try to write a lengthier note that gets blocked by the input limit of the search bar. I'll be able to evaluate whether they find it intuitive/useful to break down a lenghtier note into smaller points, or if it just causes frustration.|
| Organization | You remember that your exam will also involve reasoning about the correctness and runtimes of insertion sort, quicksort, and heapsort. Walk me through how you would make notes for those, as well as how you would organize them.| Organizing points into topics is the next step in the general workflow, and testing for it also allows me to see how easily users can discover features like the click and drag to put multiple points into the same topic and the move to topic button in the editor. In my cognitive walkthrough, I already anticipate the restriction that a point can only be in one topic, but a user may see topics as decks similar to other studying software. I can check how a user feels about the restriction, as well as how they work around it.|
| Search     | In the collection there's a point stating that quicksort's worst-case input is when the input is already sorted. Change the point to state that the worst-case input, assuming you select the first element of the list as the pivot, is a sorted list. | Task lets me evaluate whether it's intuitive for a user to search for a point by content/name. Ease of searching needs to be tested to justify the decision to not have every point always attached to a topic.|
| Recall | You want to check your understanding of the correctness and runtime of mergesort. Walk me through how you would do that. |Task represents the typical study workflow app is trying to make easier. I can evaluate the gulf of execution between my understanding that you select a set of points to create a prompt that you check recall on, and the user looking at the interface for the first time. I can also check if a user understands what the app stores after they grade themselves.
| Schedule | The collection has a due prompt to explain the proof of correctness for countingsort. Walk me through how you would find this prompt and the points within it to review. |This task lets me see how intuitive it is that scheduling is attached to prompts instead of points. It lets me see if a user understands how to see the points within a prompt. I can also probe if they see a connection between the number of points they mention and how the due date changes. |
|Sharing | Your friend Matthew is also studying for algorithms, and he's shared with you a prompt that's useful for studying. Show me how you'd find and use that prompt. | Lets me assess the learnability of making a snapshot of someone else's prompt. I can check if a user understands that sharing in this app isn't a realtime share like google docs. I can also check if they know what will happen to the original copy's scheduling after they make an attempt.
| Promotion | Within the collection, there are some points that have been missed multiple times. Walk me through how you'd find these points and write answers for them|From this task, I can check if the user understands that the suggested cards queue is a way to find points that have been missed multiple times.
